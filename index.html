Investing · FinTech

WealthKit

6 screens — tap any one to open it full size.

Problem: Most investing apps hardcode their screen states, so every layout change needs an App Store release. WealthKit is built server-driven: the backend describes the flow, the client renders it.

Result: A net-worth hero, an allocation ring and a tabular ledger that all read at a glance — and a light grey ground with inset grouped cards, the most native surface Apple ships.

  • Server-driven UI — new flows ship without a release
  • Allocation donut and 40×16pt sparklines drawn in Swift Charts
  • Amount keypad with count-up animation and a masked privacy state
  • Keychain + Face ID, with a real Reduce Transparency fallback
  • Light and dark sets, both signed off

Training · Health

FitnessPro

7 screens — tap any one to open it full size.

Problem: A training app is read mid-set, one-handed, with about two seconds of attention. Anything that needs a second look has already failed.

Result: Dark-locked by design, with no cards at all — the rings and the heart-rate zone bands are the surfaces. One giant metric, then a dense set grid, and nothing in between.

  • Progress rings, HR zone bands and a vertical zone bar
  • Set/rep grid, weight ruler and rest timer as first-class controls
  • Exercise demos: two public-domain frames crossfaded, gated behind prefers-reduced-motion
  • Consistency matrix and pace ladder for the history screen
  • Accent derives from one hex — the whole zone ramp re-maps with it

Commerce · Editorial retail

ShopEase

6 screens — tap any one to open it full size.

Problem: Marketplace apps all converge on the same look: a dense grid, a red sale badge, a card around everything. That template makes every product look like every other product.

Result: A curated-objects shop set on warm paper, in an editorial register — photography sits directly on the ground with no container, prices are ink, and the accent is reserved for a markdown. The chrome is a text-only dock; the whole app has exactly one glass element.

  • Eighteen CC0 object plates, licence asserted per item at download
  • Studio backdrops knocked out and recomposited onto the app's own paper
  • Size run with sold-out struck through, glaze swatch row, sticky glass buy bar
  • Fraunces display over a system sans, with .19em uppercase labels
  • Light-locked: the warm sand ground is the identity, so there is no dark set

Social · Creator

SocialFlow

6 screens — tap any one to open it full size.

Problem: A social feed is judged on the photography, and most designs bury it: a card, a border, a radius and a shadow around every post, and the picture ends up as an illustration inside a UI.

Result: Pure mono, black ground, and no containers and no radius anywhere on content. Media runs edge to edge, grids run at 1pt gutters, and the only colour on the screen is the photography.

  • Forty-two CC0 frames, licence asserted per item, on one shared grade
  • Story rail: 2.5pt gradient ring unseen, hairline seen
  • Chrome that dissolves on scroll, with a compose pill instead of a plus-in-a-circle
  • 1pt-gutter mosaic with a 2×2 anchor tile
  • Inter Tight set tight and large — and nothing is ever uppercased

AI · Productivity

NativeAIStudio

6 screens — tap any one to open it full size.

Problem: Every AI client currently looks the same: a purple gradient, a sparkle on every button, a chat bubble around the assistant's text, and three bouncing dots standing in for work being done.

Result: Warm ink, no tab bar, and message turns instead of cards — the user's turn is compact and right-inset, the assistant's is full width with no container at all, and that asymmetry is the whole design. Glass appears on three things across six screens.

  • Streaming response with a soft caret — no typewriter jitter, no bouncing dots
  • Tool-run chips with icon, name, argument and duration; running is a progress underline
  • Source citations as a superscript numeral with a row beneath
  • Composer that grows to five lines, with the send fill earned by being non-empty
  • Prose is IBM Plex Sans; every machine-generated fact is IBM Plex Mono

MediaPerformance-first user experience

Media Streaming Platform / Entertainment

Situation: A media streaming app had main-thread asset loading blocking the UI — users noticed sluggishness on landing, directly impacting engagement.

Making content delivery faster and smoother.

The goal was to improve performance and modernize parts of the codebase while supporting TV-linked entertainment experiences. I migrated code to Swift and improved landing page responsiveness through background-threading and refactoring.

  • Solution: Background-thread asset cache, Swift migration, threading refactor
  • Stack: Swift, Objective-C, UIKit
  • Impact: 20–30% faster landing page load performance

Before: main-thread asset loading blocking UI. After: 20–30% faster measured in Instruments.

FintechAuditable security, on device

FinVault / Self-directed reference build — public source

Situation: Founders can't tell from a résumé whether an iOS engineer has shipped regulated software, and most portfolio banking apps are a polished shell over mock data.

A banking app where every security claim links to running code.

I built a full retail-banking iOS app on a live Postgres backend — biometric vault, MFA fund transfer, wealth analytics — architected so a reviewer can audit the security story in sixty seconds instead of trusting a README. It shipped on bundled fixtures first, then migrated to live Supabase with row-level security and server-side Edge Functions: fifteen repositories changed implementation, zero view models changed.

  • Solution: MVVM + Coordinator, protocol at every layer boundary, typed errors end to end
  • Stack: Swift, SwiftUI, @Observable, async/await, Swift Testing, Supabase (Postgres + RLS, Edge Functions)
  • Impact: 31.7k lines across 17 feature modules, 94 deterministic tests, zero third-party runtime dependencies

The security table states how far each claim is actually wired — certificate pinning and App Attest ship deliberately inactive, with the blocker named on each.
