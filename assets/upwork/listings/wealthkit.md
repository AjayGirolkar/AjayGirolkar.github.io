## Description

I build native iOS apps in SwiftUI for finance products — portfolios, holdings, orders, spend feeds, goals.

Eleven years of iOS, most of it inside global banks and financial firms. Finance apps fail on the details — a rounding error, a stale balance, a chart that stutters on a year of data, a screen that leaks a number it shouldn't. I have shipped through those reviews, so I build for them from the first commit.

**What you get**

- Production SwiftUI screens, not prototypes
- MVVM + Clean Architecture, so your team can extend it
- A design token layer: colors, type scale, spacing, radii
- async/await networking. No third-party dependencies unless you ask
- Light and dark mode, Dynamic Type, VoiceOver labels
- Charts and animated states built with SwiftUI Charts
- An Xcode project that builds clean the first time you open it
- A Loom walkthrough of the code and how to extend it

**How it runs**

Day 0 you send designs, target iOS version and API docs. Day 2 the design tokens, navigation shell and models land and you get a build to run. From there feature screens go up daily against real or mock data. At handoff you get a code walkthrough, your revision round, and a checklist for App Store submission.

## FAQ

**Do you write Swift or use a cross-platform framework?**
Native Swift and SwiftUI only. No React Native, no Flutter, no web view wrappers.

**Will I own the code?**
Yes. Full source, in your repo, MIT-clean. No license fees and no runtime tied to me.

**What iOS version do you target?**
iOS 17 and up by default, built to look correct on iOS 26. Tell me if you need iOS 16.

**Can you work against my existing codebase?**
Yes. Send me repo access at kickoff. If the project is UIKit, I add SwiftUI screens through `UIHostingController` so nothing else breaks.

**Do you build the backend too?**
No. I consume your API. If you don't have one yet, the Starter tier runs on mock data so the UI is ready when your backend is.

**What if I don't have designs?**
Send a reference app or a rough sketch. I design to a token system either way — that is included, not extra.

**Why is your delivery longer than other sellers?**
Because I quote the timeline I will actually hit. Finance UI has states other apps skip: pending, partial fill, market closed, network loss mid-order. Those are the ones that get you rejected.

**Can we talk before I order?**
Yes, and you should if your scope is unusual. Message me and I will tell you honestly which tier fits or whether to skip the catalog and post a custom job.

## Project steps (workroom checklist)

Upwork owns the three bookends in the form ("client purchases and sends requirements", "you
complete the project", "client reviews and approves"). These six are the ones you add. Same list
for all three tiers. Buyer language, not tech language — one visible outcome per step.

1. **Requirements locked**
   Send me your designs, target iOS version, API docs and repo access. Delivery clock starts once this is in.
2. **Kickoff call and plan**
   15-minute call. I confirm the screen list and the order I build them in, so there are no surprises later.
3. **First build in your hands**
   App skeleton, navigation and your colors and fonts are in. You get a build you can run on your own iPhone.
4. **Screens built**
   Your screens go up against real or mock data, including loading, empty, error and offline states. Pushed daily so you can watch it come together.
5. **Polish and walkthrough**
   Charts, animations, dark mode and accessibility done. You get a short video explaining the code and how to extend it.
6. **Your revisions, then handoff**
   You send one list of changes. I fix them, you confirm, and the full source code is yours.
